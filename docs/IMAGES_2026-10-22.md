# Durable image upload

Enable only after DataDongBo image schema/API is deployed. Set `IMAGE_HOLD_ENABLED=true` on HDoi, namespace matching ChamCong, Drive folder and OAuth refresh credentials (or existing service account). API and worker inherit the same named `image-data` volume in Compose. Credentials stay in deployment secrets; images remain private.

Authenticated routes: `PUT /v1/images/:imageId/chunks/:index` with `{namespace,imageId,uploadKey,field,slot,index,total,chunk}` (base64), `GET /v1/images/:imageId?namespace=...`, `POST /v1/images/status` with `{namespace,imageIds}` (max50), `GET /v1/images/:imageId/content?namespace=...`, `POST /v1/images/:imageId/retry` with namespace, `POST /v1/images/:imageId/links` with namespace and links `{entity,recordId,field,slot,version}`. `GET /v1/images/capabilities` checks volume writability. Never send the service token to the browser.

Chunks and manifest commit with fsync/atomic rename before acceptance. Image limit5MiB; JPEG/PNG/WebP signatures validated. SHA256 conflict returns409; IDs permit lowercase hex24–64 only. HOLD/UPLOADING/RETRY/FAILED read from disk; COMPLETED content returns metadata for ChamCong's private Drive gateway. Completed bytes are removed only after verified metadata/media and a committed manifest.

Separate `images` BullMQ concurrency2 and `imageMetadata` concurrency2 do not consume Sheets admission. Journal stores upload and metadata intents; startup and15second sweeps restore queue loss. Active filesystem leases renew every30seconds with180second expiry. Drive ID is allocated and committed before upload; retries inspect/reuse that ID. Retry-After and exponential jitter persist in manifest; sweeps never reset backoff. After10 attempts or15minutes, FAILED keeps bytes and emits sanitized alert. Explicit retry starts a new retry budget without changing ID. Partial RECEIVING chunks older24hours reset; accepted pending/failed images never expire.

Metadata endpoint `/v1/cham-cong/images/upsert` uses stable version/timestamp; links `/v1/cham-cong/images/link` persist independently in manifest. Metadata outage cannot restart image upload. Back up the image volume including manifests; retain it on rollback. Do not remove the resolver after any image references are accepted. Monitor filesystem free bytes, FAILED states and queue health through existing operations monitoring; ENOSPC causes request failure rather than acknowledging undurable bytes.

Validation: `npm test` includes filesystem restart/queue recovery, timeout reuse, media verification rejection, backoff, concurrent lease and metadata offline fixtures. These use mocks: Redis restart, Docker restart, actual OAuth permissions and Google Drive upload are deployment smoke checks, not claimed live tests.
